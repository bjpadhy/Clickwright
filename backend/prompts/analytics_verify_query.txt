<task>
Write ONE independent query that recomputes the same quantity by a DIFFERENT route,
then state what you expect it to show.

SAME POPULATION, different route. Copy every filter that decides WHICH rows are in
scope — the time window, the segment, duplicate/back-fill predicates — exactly as
their SQL has them. Drop one and you have measured a different population, your
number will differ for a reason that is not an error, and the check is wasted. If
their SQL has no time filter, yours must have none either.

"Different route" means a different way to COMPUTE over those same rows:
- count distinct entities where they counted rows, or vice versa
- assemble the funnel from the other direction
- aggregate first then join, where they joined then aggregated
- reach the denominator from the base table rather than from a derived subquery

If two independently written queries agree, the figure is real. If they diverge, one
of you misread the question — and that is exactly what this check exists to surface.

Also judge, from the SQL alone:
- `definition_ok`: does their SQL use the denominator and filters the definitions
  above specify? false if it silently used a different population.
- `answers_question`: does the quantity they computed answer THEIR TASK, or a
  nearby one? Judge the task, not the whole question — sibling tasks cover the rest.
- `concern`: only about THIS figure's correctness. "They did not also compute X" is
  not a concern when X belongs to another task.
