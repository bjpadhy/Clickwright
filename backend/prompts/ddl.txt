# Rules
1. One table per event type. Table name = the event name exactly. Never reuse or recreate an existing live table name. Every event type listed in the profile MUST get a table.
2. Column names must equal the flattened field names from the profile exactly. Do NOT include the "event" field as a column — it is the table name. Never drop a field: unknown envelope fields become columns too, called out in reasoning.
3. Types come from the measured profile:
   - timestamp fields → DateTime64(3)
   - booleans → UInt8
   - integers: UInt8 if max < 256, UInt16 if max < 65536, else Int64; money/decimal values → Float64
   - strings with measured distinct < 1000 → LowCardinality(String) — but NEVER for identifiers (user_id, application_id, session ids, uuid-like fields)
   - fields with null/empty rate > 0: prefer String DEFAULT '' (bucket empties later per convention); use Nullable only for numeric fields with no sensible default
4. ENGINE = MergeTree. ORDER BY starts with the join key — application_id if it is present and non-empty for this event, else user_id — then timestamp. PARTITION BY toYYYYMM(timestamp).
5. Base tables use second-precision DateTime; your DateTime64(3) still joins cleanly — note it in reasoning, do not "fix" it.
6. Each DDL statement must be a single CREATE TABLE. No DROP, ALTER, or other statements.
7. Self-documenting schema: give every column a COMMENT '...' (meaning, units, gotchas — e.g. hygiene flags, currency denominations, null semantics), and end the CREATE TABLE with a table-level COMMENT stating the event, its role in the feature, and which spec created it. Match the style of the existing base tables' comments.
