The Problem

Getting from raw events to
trustworthy analytics is slow,
brittle, and manual.

Schema design is guesswork

Engineers pick ordering keys and types by intuition. Wrong choices are immutable — a bad key means rebuilding the table.

Context lives in people's heads

Metric definitions, data quirks, known issues — scattered across Slack, docs, and tribal knowledge. Every new analyst starts from zero.

AI analytics hallucinate numbers

LLM-generated insights look plausible but cite figures that aren't in the data. A PM acts on a number that doesn't exist.

No audit trail

When an insight is wrong, there's no way to trace it back to the query, the schema decision, or the context that shaped it.

CLICKWRIGHT 03

Architecture

Three agents. One shared brain.

01

Instrumentation

  • Profiles every field (types, nulls, cardinality)
  • Deterministic baseline DDL from stats
  • LLM optimizes codecs, ordering keys, types
  • Cross-table coherence in one call
  • EXPLAIN AST dry-run before execution
  • DML retry separate from schema retry
02

Context

  • Append-only versioned knowledge store
  • Table docs synthesized from measurements
  • LLM writes spec summaries + metric defs
  • Detects contradictions with existing context
  • Every future agent inherits what was learned
  • Semantic retrieval for mid-analysis lookups
03

Analytics

  • Plans ≤4 tasks with proactive segmentation
  • Concurrent SQL with self-healing retries
  • Full-set digests computed in ClickHouse
  • Citation check: every number verified
  • Independent query cross-checks headline
  • Wilson confidence intervals on every rate

Agents share state through context_store in ClickHouse — never call each other directly. Runs are serialized; tasks within a run are concurrent.

CLICKWRIGHT 05

Correctness Stack

Seven layers between the LLM and the PM.

Quality is the hard constraint. A slower right answer beats a fast wrong one.

☑

SQL Guard

readonly=1, banned keywords, single statement, LIMIT cap. The model cannot mutate data.

⚙

Full-Set Digest

Population stats computed over every row in ClickHouse. No extrapolation from samples.

⚠

Sanity Gate

Rates >100% flagged. Empty results dropped. Low sample sizes warned. All over the full set.

🔍

Citation Check

Every number in prose must exist in the SQL results — or be a verified arithmetic of two that do.

±

Wilson Precision

95% confidence intervals computed from the actual denominator. Reported with the figure, not separately.

✓✓

Execution-Backed Verification

An independently written query recomputes the headline figure. Disagreement drops confidence to low.

⏳

Established Figures

Follow-up answers carry prior figures + denominators. A changed denominator is explained, never silent.

👤

Human Approval Gates

DDL and context changes require explicit human approval. The agent proposes; the human decides.

Built With

Production-grade from day one.

ClickHouse Cloud

Database

Event tables, knowledge store, run history, insight cache, dashboards — all in one engine. Codecs, TTL, and ordering keys optimized per table.

Claude Sonnet 5

LLM

Best structured-output reliability for DDL + SQL + JSON. Effort pinned to medium — schema-validated prompts don't need extended thinking.

Langfuse Cloud

Tracing

Every span, generation, and score queryable. Numeric scores (self-heal attempts, citation failures) as sortable columns.

TypeScript

Backend

Strong typing + Zod runtime validation on every LLM output. Async-native for concurrent task execution.

React + Vite

Frontend

SSE streaming for live pipeline steps. Chat UI with insight cards, charts, segment tables, and confidence badges.

Zod

Validation

Every LLM response is parsed through a strict schema. Malformed output triggers self-healing retry with the verbatim error.

CLICKWRIGHT 07

What the PM Gets

Not dashboards. Answers.

Headline with the number that matters

Every insight leads with the one figure the PM needs — not a data dump.

"Express Checkout lifts checkout-to-purchase conversion by 12.3pp over standard (67.0% vs 54.7%, n=1,007 vs 3,412)."

Findings tagged by type

Drivers (what explains it), segments (where it concentrates), caveats (what to watch), known issues (linked by ID).

SEGMENT: "The gap is widest on iOS in the UAE — 67.7% Express vs 41.8% standard — consistent with K1 (OTP autofill regression)."

Charts and tables from the SQL

Bar/line charts and segment tables rendered directly from query results. Value formats (%, count, currency) inferred from column names and SQL.

Chart: "Step-through rate by funnel stage: iOS vs Android" — 8 bars, lowest highlighted in coral.

Confidence you can trust

Computed from Wilson intervals, sanity flags, citation retries, and an independent verification query. Never the model's self-assessment.

Confidence: HIGH — "±2.1pp on conversion_rate (n=6,715); an independently written query reproduced the figure."
